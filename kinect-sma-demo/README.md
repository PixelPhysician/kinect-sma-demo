# Markerless motion capture in paediatric SMA — interactive demo

A Streamlit application that shows what **Azure Kinect DK** skeleton recordings look
like during home-based exergaming, how the **physiotherapy movement protocol** is
structured across a full session, how **session quality control** works, and how the
**12 canonical upper-limb kinematic features** are derived.

> **Every recording in this repository is synthetic.** The five session files are
> generated by `make_demo_data.py` to imitate two contrasting motor profiles plus one
> deliberately faulty recording. No real participant data, identifiers or clinical
> scores appear anywhere.

## Sessions

| File | Length | Profile | Retention |
|---|---|---|---|
| `P01_S1` | ~20 min | weaker | retained |
| `P01_S2` | ~22 min | weaker | retained |
| `P02_S1` | ~18 min | stronger | retained |
| `P02_S2` | ~24 min | stronger | retained |
| `BAD_S1` | ~2.5 min | faulty | **excluded — fails all three filters** |

`BAD_S1` reproduces three failure modes at once: far too short, Loading and
Calibration frames present, and a 26-second stretch where a second person walks
into the frame and body tracking latches onto them instead of the participant
(taller skeleton, 780 mm further from the camera, translating across the field of
view). Those frames are visible in the viewer and dropped before any feature is
computed.

## Movement protocol

From the neutral resting position (sitting upright, arms relaxed on the thighs):

| Code | Movement | Type | Target |
|---|---|---|---|
| `EF` | Elbow flexion | continuous | 30–100° |
| `HA` | Horizontal abduction | continuous | arm-forward vs spine-forward 0–70°, upper arm vs spinal down 30–80°, forearm near horizontal 77–113° |
| `HR` | Head rotation | sequential | ~45°, then back to neutral (−10° to +10°) |
| `TE` | Thoracic extension | sequential | reach ~190°, then return |
| `OC` | Hand open / close | sequential | fist 30–90°, then opening 100–180° |
| `REACH` | Lateral reaching | continuous | — |

Both synthetic participants attempt the same protocol. The weaker profile achieves a
smaller fraction of it and compensates with the trunk, which is what makes the
features separate.

## The 12 features

| # | Key | Display name | Domain |
|---|---|---|---|
| 1 | `norm_jerk_R` | Log Dim. Jerk (LDLJ) | Temporal |
| 2 | `elbow_rom_R` | Elbow ROM (deg) | Joint |
| 3 | `shoulder_flexext_rom_R` | Shoulder Flex/Ext ROM (deg) | Joint |
| 4 | `shoulder_abdadd_rom_R` | Shoulder Abd/Add ROM (deg) | Joint |
| 5 | `shoulder_girdle_rom_R` | Shoulder Girdle ROM (normalised) | Joint |
| 6 | `neck_rotation_rom` | Neck Rotation ROM (deg) | Joint |
| 7 | `neck_flexext_rom` | Neck Flex/Ext ROM (deg) | Joint |
| 8 | `thoracic_ext_rom` | Thoracic Extension ROM (deg) | Joint |
| 9 | `workspace_R_m3` | Workspace Volume (m³) | Spatial |
| 10 | `vel_hand_R_mean` | Mean Hand Speed (m/s) | Temporal |
| 11 | `trunk_comp_R` | Trunk Compensation Ratio | Functional |
| 12 | `pct_above_shoulder_R` | % Time Above Shoulder | Functional |

Angular and excursion features are reported as **maximum minus minimum**. For the
animation they are re-expressed as instantaneous, rolling (4 s) or cumulative traces.

## Pipeline

Frames are kept only where the sensor reported exactly one body and the game was in
the gameplay phase. Joints below Medium tracking confidence are set to missing, gaps
up to five frames are linearly interpolated, positions are low-pass filtered with a
4th-order zero-phase Butterworth at 5 Hz, and samples implying a velocity above
3 m/s are rejected as tracking glitches.

Session retention requires all three of: at least 9000 frames, at least 50 % of
frames in the gameplay phase, and 0 % of frames in an unexpected phase
(Loading, Calibration, Settings, ChangePlayer).

## Run locally

```bash
pip install -r requirements.txt
python make_demo_data.py --npz-only    # ~15 s, writes data/*.npz
streamlit run app.py
```

The app generates the data itself on first launch if `data/` is empty, so you can
clone and run `streamlit run app.py` directly.

## Data artefacts and file size

A 20-minute session at 30 Hz is ~36,000 frames × 32 joints — roughly **200 MB as
uncompressed JSON**, which will not fit in a Git repository. `make_demo_data.py`
therefore writes three things per session:

| Artefact | Size | Purpose |
|---|---|---|
| `<name>.npz` | ~15 MB | compact float32 arrays, what the app reads |
| `<name>.json.gz` | ~36 MB | the complete recording in the original schema |
| `<name>_excerpt.json` | ~0.5 MB | first 40 frames, pretty-printed, for inspection |

`data/` is gitignored by default. `json.load(gzip.open(path, "rt"))` reads the
gzipped file back unchanged.

```bash
python make_demo_data.py               # npz + json.gz + excerpt (~1 min)
python make_demo_data.py --npz-only    # npz + excerpt only (fast)
python make_demo_data.py --minutes 4   # short sessions, for quick testing
```


## Working with your own recordings on a laptop

Open `app.py` and edit the configuration block at the very top:

```python
# =========================================================================
#  CONFIGURATION - edit this block only
# =========================================================================
LOCAL_DATA_DIR = r"C:\Users\you\Documents\video tela patients"
LOCAL_CACHE_DIR = ".kinect_cache"

PATIENT_ID_MAP = {
    # "b1a7f0c2...": "P01",
    # "c9dde431...": "P02",
}
```

Then `streamlit run app.py`. The folder is searched **recursively** for `.zip`,
`.json` and `.json.gz` files, so the original zipped session archives work
untouched. Everything else in the app behaves identically.

**What happens on first launch.** The app lists the recordings it found and asks
you to press *Import*. Each file is read once and converted into a compact `.npz`
inside `<your folder>/.kinect_cache/` — roughly 20–60 s per 20-minute session, and
about 15 MB each. After that, loading is instant. Delete `.kinect_cache` to force a
re-import. The originals are never modified and nothing leaves the machine.

**Things that adapt automatically:**

- the joint list and its ordering are read from the file rather than assumed
- the `labels` string is decoded through `labelsNames`, so field positions can move
- movement blocks are inferred from the completed-movement flags, since real
  recordings carry no explicit movement track
- test–retest CV% pairs any two sessions sharing a name stem, e.g.
  `b1a7f_1339830…` and `b1a7f_1339831…`

**On identifiers.** `PATIENT_ID_MAP` exists so the interface shows `P01` instead of
a raw `patientId` hash. It is optional — without it the file name is used. Keep real
hashes, file names and the `.kinect_cache` folder out of any repository you push;
the shipped `.gitignore` already excludes `data/`, so add your own folder to it too
if it lives inside the project.

## Deploy on Streamlit Community Cloud

1. Push this repository to GitHub (without `data/`).
2. Go to <https://share.streamlit.io>, click **New app**, pick the repo and branch.
3. Set the main file to `app.py` and deploy. The data generates on first load.
